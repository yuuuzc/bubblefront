# 泡泡前线 · 玩法与架构设计

## 1. 定位

QQ 堂的核心乐趣是"放一颗泡，改变整张地图的通行权"。本作的扩展方向：

> 把泡泡从"定时炸弹"升级为**元素法术 + 地形改造 + 团队博弈**，
> 同时用确定性模拟把"竞技可信度"（回放、校验、复盘）做成基础设施。

设计约束：单局 ≤ 4 分钟、规则 10 秒能看懂、深度来自元素组合而非数值堆叠。

## 2. 核心循环

```
探路/挖砖 → 获得元素与强化 → 用泡泡切割地图、制造区域
   ↑                                            ↓
救人/冲刺 ← 被困博弈 ← 元素反应制造爆发 ← 逼迫对手走位
```

- **挖砖**是经济：软砖给分、掉道具，道具决定你能打什么combo。
- **区域**是资源：霜面减速、毒气待点燃、余烬封路，残留区域是下一波反应的引信。
- **被困**是节奏点：5 秒困泡制造"救人还是抢攻"的决策，而不是瞬时减员。

## 3. 规则明细

### 3.1 移动

- 19×13 格竞技场，硬边界 + 偶数坐标石柱 + 种子化软砖（62% 密度）。
- 定点坐标：1 格 = 256 子单位，速度 12 子单位/tick（≈2.8 格/秒）。
- 网格车道移动：转向时把**离开的那根轴**吸附到车道中心，附带过弯滑行与贴墙滑动，
  手感接近 QQ 堂的"贴墙就走直线"。
- 自己刚放的泡泡在身体仍与其相交时可穿行，完全离开后变为实体——可以放泡封路再绕走。

### 3.2 泡泡

- 经典规则：泡泡只放在自己脚下这格，该格已有泡泡或不是地板时放不出来；
  同屏数量、臂长由道具成长（上限 6 颗 / 7 格）。
- 引信 260 tick（4.3s），速爆道具缩短到 150。
- 十字臂：硬砖阻挡，软砖被炸毁并终止该臂（焰泡除外），命中其他泡泡则连锁。
- 连锁每层 +1 臂长（最多 +2）并给连锁分，层数上限 12。

### 3.3 元素

| 元素 | 直接效果 | 残留 |
| ---- | -------- | ---- |
| 普通 | 标准十字 | 无 |
| 焰 | 烧穿软砖继续延伸，热区更久 | 余烬 |
| 霜 | 热焰后留下霜面 | 霜面：减速 |
| 雷 | 2 格（切比雪夫）内泡泡隔空起爆 | 无 |
| 毒 | 气域长时间致命 | 气域：可被任何爆破点燃 |

### 3.4 元素反应（数据驱动）

反应判定发生在爆破**臂计算之前**：泡泡所在格与四邻的残留区域（含"热区冷却后将变成的
残留"）参与匹配，因此曳光可以加长本次爆炸。

| 组合 | 名称 | 效果 |
| ---- | ---- | ---- |
| 焰+毒 | 爆燃 | 3×3 火球，臂长 +1 |
| 雷+毒 | 引信 | 全图气域瞬间转火焰 |
| 霜+雷 | 超导 | 6 格内所有元素泡同时引爆 |
| 焰+霜 | 灭焰 | 5×5 蒸汽：清除并封锁火焰 |
| 焰+雷 | 曳光 | 本次臂长 +2 |
| 霜+毒 | 凝滞 | 霜面时长翻倍 |

### 3.5 被困、救援与生命

- 被热区命中：有护盾则挡一次，否则**困入水泡** 300 tick，位置吸附到格中心。
- 救援：他人与被困者同格接触累积进度（队友 1/tick，敌方 0.5/tick），24 点满。
  队友救援双方各得冲刺，敌方"赎回"会得分——放人也是一种交易。
- 倒计时结束未获救：爆泡，失去一条命，100 tick 后在出生点复活（90 tick 无敌）。
- 三条命耗尽即出局；全队出局判负，240 秒到时按队伍总分判定。

### 3.6 极限冲刺（pop-dash）

新热区出现在你身边 1 格内却没命中你 → 26 tick 加速（+14 子单位/tick）。
奖励"贴着爆炸走位"，让高手能用风险换机动。

### 3.7 道具与计分

道具藏在软砖下（25% 概率），炸开才显形：泡+1 / 力+1 / 速+1 / 护盾 / 速爆 /
四种元素 / 稀有命+1。抽取按权重，且对已满级属性重抽。

计分：软砖 10 · 命中 120 · 救援 60 · 淘汰 320 · 连锁每层 25 · 拾取 15。

## 4. AI 设计

机器人与人类**共用同一个命令入口**（方向位 + 放泡位 + 换元素位），没有任何特权。

1. **危险图**：对每颗在场泡泡调用真实 `blastPlan`，按引信剩余换算到达时间威胁。
2. **时间感知 BFS**：软砖可通行但有挖掘代价（70 tick），到达晚于爆炸的格子不可走。
3. **放点评分**：命中敌人 +130 / 波及队友 −70 / 挖砖 +15（在计划路径上再 +22）/
   自热 −6，阈值 8；泡数已满直接放弃，避免"想放放不下而站着被炸"。
4. **逃生验证**：把假想泡泡真的插入世界再跑一遍 BFS，确认放完有活路才放。
5. **人性化**：反应延迟（简单 14 / 普通 6 / 困难 3 tick）与失误噪声；
   动作位只保持一个 tick，和真人的点按一致。

## 5. 确定性与回放

- 固定 60Hz，整数运算，mulberry32 的种子状态保存在模拟内；表现层的随机不进模拟。
- `stepSim` 顺序：命令 → 朝向/动作沿 → 移动 → 区域衰减 → 引信与爆破 →
  命中/冲刺 → 被困/救援 → 道具 → 复活 → 计时器 → 胜负 → tick++。
- 哈希覆盖全状态（含 RNG、泡泡序号、每个字符串的全部字符），是回放校验契约。
- 回放 = 种子 + 玩家配置 + 人类命令差分；机器人重新模拟。
  实测一整局几百字节到几 KB，播放结束比对最终哈希与 tick 数。
- 同一套代码跑在浏览器与 Node：测试、无头对局、平衡统计都不用浏览器。

## 6. 扩展指南

- **加道具/元素/反应**：只改 `data/powers.json`；新反应效果在
  `systems/bubbles.js` 的 `detonate` 里加一个 `case`。
- **调平衡**：只改 `game/config.js`；用 `node tools/headless.js <seed> <ticks>` 观察。
- **加模式**：`main.js` 的 `buildSpecs` + `resolve.js` 的 `checkWin`。
- **换美术**：见 `docs/ASSETS.md`，渲染器只认图集帧名。

## 7. 路线图

- 网络对战：模拟已是"命令进、状态出"，可先做主机权威 + 回放校验，再谈回滚。
- 观战与复盘时间轴（拖动 = 重新模拟到目标 tick，配合周期性快照）。
- 教程/元素试炼场：固定残局引导六种反应。
- 地图编辑器与赛季规则（毒圈收缩、随机事件）。
